# Base Engineering Guide

## Core principles

```text
eng/ is the stable engineering API.
Platform launchers stay thin.
Complex orchestration lives in tested application code.
Validation depth is independent of target and execution locus.
Validation may be resumable.
Human review is a repository-local milestone completion gate.
```

## Human review commands

Repositories with active human-review gates should expose equivalent commands through each supported launcher for:

```text
review-list [--milestone <id>] [filters]
review-show <review-id-or-alias>
review-request --milestone <id> ...
review-record <review-id-or-alias> <decision> ...
review-reopen <review-id-or-alias> ...
review-check --milestone <id>
```

For example, a supported repository may expose thin `.sh`, `.ps1`, or other platform launchers that map these operations to the same shared engineering semantics.

Interactive review commands may accept ephemeral aliases generated by the latest `review-list` invocation.

Durable automation, milestones, requests, and records must use canonical review IDs.

`review-check` validates only the completion gate for the named milestone.

It must not invalidate or reopen completed reviews because later commits changed the repository.

Alias resolution, decision recording, milestone filtering, and structural validation should live in the shared engineering command implementation rather than duplicated shell logic.
